# FinStream evaluation harness

Measures whether the three-agent pipeline applies, end to end, the capabilities each
agent demonstrates in isolation — a capability-conditioned view of pipeline reliability —
and audits PII hand-off between the deterministic sanitizer and the LLM-backed agents.

```
eval/
├── generate_dataset.py   labelled transactions + graph/vector seeds (deterministic)
├── run_eval.py           drives /api/eval/** against the live stack (resumable; --mock for dry runs)
├── analyze.py            metrics, tables, figures -> results/analysis/
├── requirements.txt
└── data/                 generated by generate_dataset.py
```

## Experimental design

| Stage | What runs | What it measures |
|---|---|---|
| `isolated` | each agent alone on every transaction | subtask capability: masking, prompt-level leak, category accuracy, risk correctness |
| `pipeline` | full chain via `processTransactionSync` | composite success; output-level leak; gap vs. the isolated prediction |

Two hand-off modes are compared on the same transactions:

| Mode | LLM agents receive | Corresponds to |
|---|---|---|
| `raw` | the raw `RawTransaction` | original pipeline behaviour |
| `sanitized` | masked fields + scrubbed description (`SanitizationAgent.sanitizeForLlm`) | `finstream.pipeline.sanitize-before-llm=true` |

Five transaction conditions (400 items by default):

| Condition | n | Purpose |
|---|---|---|
| `clean` | 200 | baseline; PII only in structured fields |
| `pii_in_text` | 80 | email / IBAN / name / IP / phone embedded in `description` |
| `obfuscated_pii` | 40 | spaced names, `[at]` emails, spaced IBANs — scrubber limits |
| `ood_merchant` | 40 | merchants absent from the graph and the vector store |
| `prompt_injection` | 40 | instructions inside `description` on fraud-ring merchants |

Ground truth for fraud is derived from the seeded graph (hop distance to the nearest flagged
merchant) using the risk hierarchy documented in `GraphAnomalyAgent`.

## Running

1. Start the stack and the app with eval endpoints enabled (see `EVAL-RUNBOOK.md`).
2. Generate data, seed stores, run, analyse:

```bash
cd eval
pip install -r requirements.txt
python generate_dataset.py
python run_eval.py --seed-stores
python run_eval.py --stages isolated,pipeline --modes raw,sanitized
python run_eval.py --stages pipeline --modes raw,sanitized --repeats 3   # optional: consistency
python analyze.py
```

Runs are resumable: re-running skips transactions already present in `results/*.jsonl`.
`--mock` exercises the whole harness without any services (numbers from mock mode are
not results).

## Outputs

* `results/analysis/summary.md` — all tables
* `results/analysis/summary.json` — machine-readable
* `results/analysis/figures/` — `composite_gap.png`, `leak_rates.png`, `risk_by_hops_*.png`
* `results/analysis/scored_*.csv` — per-transaction scores
